## Data

In its 2023-05-14 announcement
[Jazz Playlist Updates: New 1,410 Jazz Standards][news], iReal Pro introduced
the Jazz 1410 playlist. As of the survey date, the playlist link in that post
points to [Jazz 1460 Standards][playlist] on the official forums. This analysis
covers the Jazz 1460 playlist obtained from that link.

| Item | Value |
|---|---:|
| Playlist | Jazz 1460 |
| Songs | 1,460 |
| Bars after expanding repeats | 50,451 |
| Chord occurrences | 70,794 |
| Distinct full chord symbols | 1,094 |
| Distinct chord qualities | 60 |
| Slash chord | 3,079 |

The percent-decoded `irealb://` payload was 455,946 bytes.

The HTML and the expanded JSON used for the analysis are kept locally and are not
committed to Git.

## Method

1. Took the first `irealb://` playlist link on the official forum page.
2. Percent-decoded the URL with the public [pianosnake/ireal-reader][reader]
   implementation and split it on `===` into 1,460 songs plus the playlist name.
3. Decoded and parsed the chord progressions with the same implementation,
   expanding `x`, `r`, repeated sections and the supported D.C. / D.S. jumps into
   a flat list of bars.
4. Aggregated the expanded JSON with the [analysis script][analysis-script].
5. Counted each chord symbol once, with no weighting by beats or duration.
6. Counted slash chords under the root and quality of the main chord, plus
   separately as slash chords. The bass note is not added to root frequencies.
7. Included alternate chords as the parser returned them, without distinguishing
   them from main chords.
8. Counted only the chord tones a symbol names explicitly. Tones a player might
   add, such as the 9th over `C13`, are not counted. The quality-to-interval map
   is in [`src/intervals.js`][intervals-map].
9. Derived chord-tone spellings from the interval's size (how many letter names
   it spans) and its semitone count. The `♯9` of `E7♯9` is F𝄪, kept distinct
   from the enharmonic G.

## Limitations

- Jazz 1460 is one specific iReal Pro playlist, not a random sample
  representative of jazz as a whole or of other genres.
- Results shift with the reharmonization chosen for a given song.
- Each chord symbol counts once, with no weighting by beats, tempo or number of
  passes.
- Repeats are expanded, but the parser's playback order was not verified against
  the iReal Pro app's own playback.
- Alternate chords are included, so these are not statistics about "only the
  chords the accompaniment engine actually plays".
- The official protocol's root list centers on the usual 17 spellings, so root
  frequencies cannot be assessed for `F♭`, `E♯`, `B♯` or double accidentals.
  Their frequency as chord tones is counted under "Chord-tone spelling and
  double accidentals".
- Interval counts follow the spelling of the chord symbol, not an actual voicing.
  Omitted fifths and added tones absent from the symbol are not reflected.
- There are 1,094 distinct full chord symbols, so only the top 25 are listed
  here. Roots and qualities are listed in full.

## Reproducing the analysis

From a playlist JSON decoded and expanded by `pianosnake/ireal-reader`, the tool
emits occurrence counts and song counts as JSON for roots, qualities, families,
full chord symbols, slash basses, key signatures, intervals and chord-tone
spellings. Run the commands below from the root of this repository.

### Aggregating a local JSON file

If decoding the HTML is unnecessary, a locally saved JSON can be aggregated
directly. The source data under `tools/ireal-analysis/data/` is not tracked by
Git.

```console
node tools/ireal-analysis/src/cli.js \
  tools/ireal-analysis/data/jazz-1460.json > /tmp/jazz-1460-stats.json
```

### Reproducing from the HTML

This needs `git` and Node.js. Clone the [pianosnake/ireal-reader][reader-revision]
revision used for the analysis into `/tmp` and pin it.

```console
IREAL_READER_DIR=/tmp/ireal-reader-662106f
git clone https://github.com/pianosnake/ireal-reader.git "$IREAL_READER_DIR"
git -C "$IREAL_READER_DIR" checkout --detach \
  662106fe60ea3f91574ddf98df0e2468a3d89e6a
```

Decode and expand the saved HTML, then pipe the output into the aggregator.

```console
node "$IREAL_READER_DIR/index.js" \
  tools/ireal-analysis/data/jazz-1460.html \
  | node tools/ireal-analysis/src/cli.js - \
  > /tmp/jazz-1460-stats.json
```

The JSON `ireal-reader` emits has the same content as the JSON saved at analysis
time, but formats line breaks in the bar arrays differently. This does not affect
the aggregated results.

To limit just the full-chord-symbol ranking to the top 30:

```console
node tools/ireal-analysis/src/cli.js --exact-limit 30 \
  tools/ireal-analysis/data/jazz-1460.json
```
